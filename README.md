# 전력·에너지 뉴스 봇

국내·해외 전력/에너지 뉴스를 자동으로 수집해 한국어 요약 카드로 만들어 텔레그램 개인 DM 으로 보냅니다.
기사 링크를 봇에게 보내면 번역까지 해서 같은 양식으로 정리해 줍니다.

```
[GE버노바, 텍사스 765kV 송전선 12억달러 수주]

▪️ GE버노바가 텍사스 ERCOT 구간 765kV 송전선 공급 계약을 따냈다.

1. 계약 규모는 12억 달러(약 1조 6천억원), 2029년 완공 목표다.
2. 변압기·개폐기 일괄 공급이며 초고압 변압기 40대가 포함된다.
3. ERCOT 는 데이터센터 수요 증가로 송전 투자 계획을 상향했다.

🔗 Utility Dive · 09월 15일
#송전망 #미국 #GE버노바
```

## `news-clipper` 와의 역할 분담

같은 `projects` 폴더의 [`news-clipper`](../news-clipper)와 다루는 종목이 거의 같습니다.
효성중공업 수주 한 건이 양쪽에 다 걸립니다. 그래서 **주제가 아니라 시점으로** 나눴습니다.

|  | news-clipper | news-bot (이 프로젝트) |
|---|---|---|
| **한 줄 정의** | 어제 뭐 있었는지 빠짐없이 훑는다 | 아침까지 기다리면 늦는 것만 알린다 |
| 언제 | 매일 07시 1회 | 뜨는 즉시 (5~15분) |
| 분량 | 32건 (4섹터 × 8건) | 하루 최대 4건 |
| 범위 | 원전·건설·유틸리티·전력기기 | 전력기기·전력망 |
| 무엇을 | **전부** — 동향·해설·전망 포함 | **확정 이벤트만** — 수주, 공시, 낙찰, 정책 확정, 착공, 프로젝트 취소 |
| 형식 | 한 줄 요약 묶음 | 카드 (세부 3~5개) |
| 링크 정리 | 없음 | 있음 (URL 보내면 번역·정리) |

**판단 기준 한 줄**: "오늘 장중에 반응해야 하나?" — 아니면 news-bot은 침묵하고 아침에 넘깁니다.

그래서 이 봇은 아래를 **의도적으로 버립니다**. 전부 아침 다이제스트에서 보게 됩니다.

- 해설·분석·기획·인터뷰·칼럼
- `~할 전망`, `~검토 중`, `~추진`, `~논의` 처럼 확정되지 않은 것
- MOU·업무협약, 전시회·세미나, 시장 규모 전망치
- 단순 주가 등락, 증권사 목표주가 리포트

조정 지점 두 군데:

- **야간 큐를 08시에 풉니다** (`quiet_hours.end`). 07시에 clipper 다이제스트 4건이 먼저
  도착하므로, 같은 시각에 겹치지 않게 한 시간 비켜뒀습니다.
- **원전·유가·일반 클린테크 피드를 뺐습니다.** 원전은 clipper의 원전 다이제스트(8건)가
  전담하고, 나머지는 확정 이벤트가 거의 없어 노이즈만 됐습니다.
  `config.yaml` 의 `feeds` 아래 주석 처리해 뒀으니 되살리려면 주석만 푸세요.

> 봇·토큰·API 키는 양쪽이 공유해도 됩니다 (아래 준비물 참고).

## 설치 (10분)

### 1. 저장소 만들기

이 `news-bot` 폴더를 통째로 새 GitHub 저장소에 올립니다.
**이 PC에는 git이 설치돼 있지 않으므로**, 아래 웹 업로드 방식이 가장 빠릅니다.

**방법 A — 브라우저로 업로드 (git 불필요, 권장)**

1. github.com → 우측 상단 **+** → **New repository**
2. 이름을 정하고(예: `news-bot`), **Public** 선택 → **Create repository**
3. 만들어진 페이지에서 **uploading an existing file** 링크 클릭
4. 탐색기에서 `C:\Users\dlack\projects\news-bot` 폴더를 열고,
   **안에 있는 항목 전부를**(`src`, `scripts`, `.github`, `state`, `config.yaml`,
   `README.md`, `requirements.txt`, `.gitignore`) 드래그해서 올립니다
   — 폴더째가 아니라 **내용물**을 올려야 경로가 맞습니다
5. 아래 **Commit changes** 클릭

> 숨김 파일이라 `.github` 폴더가 탐색기에 안 보이면, 탐색기 상단 **보기 → 표시 → 숨긴 항목**을 켜세요.
> 이 폴더가 빠지면 자동 실행이 안 됩니다.

**방법 B — git 설치 후 명령줄**

git을 쓰실 거면 [git-scm.com](https://git-scm.com/download/win)에서 설치한 뒤:

```bash
cd C:\Users\dlack\projects\news-bot
git init
git add .
git commit -m "init: 전력 에너지 뉴스 봇"
git branch -M main
git remote add origin https://github.com/<내아이디>/<저장소이름>.git
git push -u origin main
```

> **public 저장소를 권장합니다.** Actions 실행시간이 무제한이라 5분 주기를 공짜로 돌릴 수 있습니다.
> API 키는 코드가 아니라 GitHub Secrets 에 들어가므로 public 이어도 노출되지 않습니다.
> private 으로 하려면 `.github/workflows/bot.yml` 의 cron 을 `*/15` 이상으로 늘리세요.
> (무료 한도 월 2,000분)

## 응답 속도에 대한 솔직한 이야기

워크플로가 둘로 나뉘어 있고, 역할이 다릅니다.

| | `news-bot` (bot.yml) | `news-bot-worker` (worker.yml) |
|---|---|---|
| 하는 일 | 뉴스 수집·선별·발행 | 내가 보낸 링크·명령어에 응답 |
| 주기 | 5분 cron (실제 5~20분) | 30분마다 켜져 **15초 간격**으로 대기 |
| 응답 속도 | — | **몇 초** |

**링크를 보내면 몇 초 안에 답이 옵니다.** worker 가 상시 대기 중이기 때문입니다.
뉴스 자동 발행은 bot.yml 담당이라 5~20분 주기입니다 — 속보라도 그 정도는 걸립니다.

> **GitHub cron 은 최소 5분이고 약속을 안 지킵니다.** 혼잡하면 10~20분씩 밀리고 건너뛰기도 합니다.
> 무료 실행이라 우선순위가 낮습니다. 또 **새로 만든 저장소는 예약 실행이 시작되기까지
> 10분~1시간쯤 걸립니다** — 처음에 아무 일도 안 일어나는 것처럼 보여도 정상입니다.

**수신 메시지는 worker 가 전담합니다.** bot.yml 은 `--no-messages` 로 돌기 때문에
같은 링크에 두 번 답하는 일이 없습니다. worker 를 끄실 거라면 bot.yml 의 `--no-messages` 도
함께 지우세요. 안 그러면 링크를 보내도 아무도 답하지 않습니다.

worker 는 public 저장소라서 무료입니다. private 으로 바꾸면 무료 한도(월 2,000분)를 하루 만에
소진하므로, 그때는 worker.yml 의 `schedule` 을 지우고 필요할 때만 수동 실행하세요.

## 필터 조정하기

`config.yaml` 만 고치면 됩니다. 코드는 건드릴 필요 없습니다.

기본값은 `news-clipper` 와 역할을 나눈 상태(확정 이벤트만, 하루 4건)로 잡혀 있습니다.

**뉴스가 너무 적게 온다** → `limits.min_importance` 를 4 → 3, `limits.min_score` 를 7 → 5 로.
그래도 적으면 `src/summarize.py` 의 "publish=false 로 버려라" 목록에서 몇 줄 지우세요 —
동향 기사까지 받고 싶다면 `해설, 분석, 기획, 전망` 줄을 빼면 됩니다.

**너무 많이 온다 / 관심 없는 게 온다** → `min_importance` 를 5 로 올리면 진짜 큰 건만 옵니다.
계속 거슬리는 유형이 있으면 `blocklist` 에 단어를 추가하세요.

**특정 종목을 챙기고 싶다** → `watchlist.domestic` / `watchlist.overseas` 에 이름을 추가하세요.
워치리스트에 걸리면 점수가 4점 더해져 거의 확실히 통과합니다.

**야간 알림을 끄고 싶지 않다** → `quiet_hours.enabled` 를 `false` 로.
현재는 한국시간 01~07시에 잡힌 건(중요도 5 제외)을 큐에 쌓아뒀다가 아침 7시 이후 첫 실행 때 한꺼번에 보냅니다.
미국 뉴스가 새벽에 몰려 하루치를 다 먹어버리지 않도록 야간 몫은 `max_night_queue`(기본 3건)로 따로 막아뒀습니다.
아침에 몰아 받는 양을 늘리고 싶으면 이 값을 올리세요.

**점검 도구**

```bash
python scripts/check_feeds.py
```
```bash
python scripts/test_dedup.py
```

`check_feeds.py` 는 피드가 아직 살아있는지, `test_dedup.py` 는 같은 사건을 여러 매체가 썼을 때
한 번만 나가는지를 실제 기사 제목으로 검사합니다. `store.py` 상단의 `DUP_*` 임계값을 건드렸다면 후자를 꼭 돌려보세요.

## 비용

`config.yaml` 의 `model.id` 가 `claude-sonnet-5` 이고 `effort: low` 입니다.
키워드 점수로 1차 선별을 마친 기사만 모델에 보냅니다.
한 번 돌 때 최대 `max_candidates_per_run`(15건)까지만 호출하므로 비용 상한이 여기서 잡힙니다.
실제로는 대부분 이미 처리한 기사라 회당 0~3건 정도만 새로 호출됩니다.

기사 1건당 대략 입력 3천 토큰 + 출력 500 토큰 → **건당 약 15원**, **하루 150~300원** 수준입니다.

요약 품질이 부실하다 싶으면 `config.yaml` 에서 모델을 올리세요. 대신 비용이 약 2.5배가 됩니다.

```yaml
model:
  id: claude-opus-5    # 입력 $5 / 출력 $25 per 1M (sonnet 은 $2 / $10)
```

> 2026-09-15 기준 같은 기사로 두 모델을 비교했을 때, 고르는 기사도 버리는 이유도 수치 정확도도
> 차이가 없었습니다. 기사 요약은 판단보다 정리에 가까운 작업이라 sonnet 으로 충분합니다.

`limits.max_candidates_per_run` 이 모델 호출 수의 상한이라, 비용이 걱정되면 이 값을 낮추면 확실하게 잡힙니다.

## 구조

```
config.yaml              소스·워치리스트·키워드·한도  ← 여기만 고치면 됨
src/
  main.py                실행 흐름, 조용한 시간 처리, 텔레그램 명령어
  sources.py             RSS 병렬 수집 (직접 피드 + 구글뉴스 검색)
  scoring.py             키워드·워치리스트 점수로 1차 선별 (무료, 모델 호출 전)
  extract.py             본문 추출, 구글뉴스 링크 해석
  summarize.py           Claude 호출 → 구조화 JSON 요약 카드
  tg.py                  텔레그램 전송 + 메시지 렌더링
  store.py               중복 방지, 일일 한도, 야간 큐 (state/state.json)
scripts/
  get_chat_id.py         chat_id 찾기
  check_feeds.py         피드 생사 확인
  test_dedup.py          중복 판정 회귀 테스트
```

### 중복 제거가 이 봇의 핵심입니다

큰 수주 하나가 뜨면 국내 매체 10곳이 같은 내용을 씁니다. 실제로 테스트할 때
효성중공업 변압기 수주 한 건이 11개 매체에서 후보로 올라왔습니다.

한국어 제목은 조사가 붙어서(`빅테크에` vs `빅테크`) 단어 단위 비교가 통하지 않으므로,
**글자 3-gram 겹침** + **제목 속 금액을 유효숫자 2자리로 뭉갠 지문**을 함께 씁니다.
`3865억원` 과 `3866억` 은 같은 건으로, `1665억원 공급계약` 과 `2200억원 공급계약` 은
제목 틀이 거의 같아도 **다른 공시로** 구분합니다.
