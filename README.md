# 전력·에너지 뉴스 봇

국내·해외 전력/에너지 뉴스를 자동으로 수집해 텔레그램 채널로 보냅니다.
봇 DM 에 기사 링크를 넣으면 번역·요약해서 📝 기사 요약 채널에 올려줍니다.
일감마다 채널이 하나씩 있습니다 — [채널 배치](#채널-배치--하나의-업무-하나의-채널) 참고.

```
[GE버노바, 텍사스 765kV 송전선 12억달러 수주]

▪️ GE버노바가 텍사스 ERCOT 구간 765kV 송전선 공급 계약을 따냈다.

1. 계약 규모는 12억 달러(약 1조 6천억원), 2029년 완공 목표다.
2. 변압기·개폐기 일괄 공급이며 초고압 변압기 40대가 포함된다.
3. ERCOT 는 데이터센터 수요 증가로 송전 투자 계획을 상향했다.

🔗 Utility Dive · 09월 15일
#송전망 #미국 #GE버노바
```

## 이 봇이 하는 네 가지

2026-09-17 에 구조를 바꿨습니다. 그 전에는 "AI 가 중요도를 판단해 속보를 골라주는"
방식이었는데, 두 가지 이유로 잘 돌지 않았습니다.

- **GitHub 예약이 약속을 안 지킵니다.** 5분 간격으로 걸어둔 워크플로가 49시간 동안
  15번 돌았습니다(간격 중앙값 4시간). 4시간에 한 번 도는 봇은 속보를 줄 수 없습니다.
- **중요도 판단을 맡길수록 표본이 줄어듭니다.** 문턱을 높이면 놓치고, 낮추면 시끄럽습니다.
  판단을 사람이 하는 편이 낫다는 결론에 이르렀습니다.

그래서 **판단이 필요 없는 일은 기계가, 판단이 필요한 일은 사람이** 하도록 나눴습니다.

| 모드 | 무엇 | 언제 | AI | 어디로 |
|---|---|---|---|---|
| ⚡ **알람** | 키워드 적중 기사 | 즉시 (5분 내) | 안 씀 | 알람 채널 |
| 📰 **클리핑** | 섹터별 목록 40건 | 2시간마다 | 안 씀 | 클리핑 채널 |
| 💬 **요약** | 내가 DM 에 넣은 링크 | **10초 안팎** | 씀 | 📝 기사 요약 |
| 🏠 **주간** | 부동산 News Flow 8건 | 금요일 08시 | 안 씀 | 📋 부동산 위클리 |

알람과 클리핑이 AI 를 안 쓰기 때문에 **빠르고, 비용이 0 에 가깝고, "AI 가 잘못 버릴"
위험이 없습니다.** AI 는 내가 직접 고른 기사 하나를 정리할 때만 씁니다.

### 채널 배치 — 하나의 업무, 하나의 채널

봇 하나(`@Researchslave_bot`)가 저장소 두 개에서 다섯 가지 일을 합니다.
2026-09-18 에 **일감마다 채널을 하나씩** 주도록 정리했습니다.

| 채널 | 무엇이 오는가 | 보내는 쪽 | 환경변수 |
|---|---|---|---|
| ⚡️ 전력 알람 | 키워드 적중 기사, 즉시 | news-bot | `TELEGRAM_CHAT_ID_ALERT` |
| 📰 시간별 뉴스 클리핑 | 전력·에너지 목록, 2시간마다 | news-bot | `TELEGRAM_CHAT_ID_CLIP` |
| 📋 부동산 위클리 | News Flow 8건, 금요일 08시 | news-bot | `TELEGRAM_CHAT_ID_WEEKLY` |
| 📝 기사 요약 | DM 에 넣은 링크의 번역·요약 카드 | news-bot | `TELEGRAM_CHAT_ID_SUMMARY` |
| 📚 데일리 클리핑 | 4섹터 × 10건, 매일 07:00 | [News-Clipper](https://github.com/dlacksgud11111-tech/News-Clipper) | 그쪽 `TELEGRAM_CHAT_ID` |
| 💬 DM (Researchbot) | **입력창** — 링크를 여기에 넣습니다. `/status` 같은 명령어 응답도 여기로 | news-bot | `TELEGRAM_CHAT_ID` |

DM 은 결과가 쌓이는 곳이 아니라 **넣는 곳**입니다. 요약 카드는 전용 채널로 갑니다.
채널 주소(시크릿)가 비어 있으면 그 메시지는 DM 으로 떨어지므로, 채널을 만들기 전에도
아무것도 사라지지 않습니다.

### 알람 규칙 (config.yaml 의 `alerts`)

제목에 **(워치리스트 회사)** 와 **(사건을 뜻하는 단어)** 가 함께 있어야 울립니다.
`수주` 하나로 울리면 하루 수십 건이 오고, 회사명만으로 울리면 증권사 리포트까지 다 옵니다.

반덤핑·관세처럼 회사명이 안 붙는 사건은 `require_company: false` 로 따로 뺐습니다.
모든 규칙은 **업종 관문**을 먼저 통과해야 합니다 — 이게 없으면 `착수`·`준공` 같은
단어 때문에 도시재생 준공 기사까지 알람이 울립니다.

**알람이 너무 적으면** `words` 에 단어를 더하거나 `require_company` 를 끄세요.
**너무 많으면** 반대로 하거나 `blocklist` 에 단어를 더하세요.

### 클리핑 (config.yaml 의 `clipping`)

매 실행마다 버퍼에 쌓고 `interval_hours` 마다 한 번에 보냅니다. 훑을 수 있는 분량을
유지하려고 세 겹으로 자릅니다 — 전체 `max_items`(40), 섹터당 `max_per_sector`(8),
회사당 `max_per_company`(3). 큰 수주가 터진 날 한 회사가 목록을 다 먹는 것을 막습니다.

같은 사건을 여러 매체가 쓰면 한 줄로 묶고 `외 N곳` 으로 표시합니다.
알람으로 이미 나간 기사에는 🚨 가 붙습니다.

### 부동산 주간 News Flow (config.yaml 의 `weekly`)

전력·에너지와 아무 상관이 없는, 별개의 일입니다. LS증권 **'부동산 Weekly Data'** 의
'지난주 주요 News Flow' 칸에 붙일 기사 8건을 **매주 금요일 오전 8시**
📋 부동산 위클리 채널(`weekly.channel`)로 보냅니다. 소스도 따로입니다 — 위 전력 피드를 쓰지 않고 구글 뉴스에서 부동산 검색어
15개를 돌립니다. 대상 기간은 **지난주 금요일 00:00 ~ 이번주 금요일 08:00 (KST)**.

메시지가 두 개 옵니다.

1. **메모** — 기간, 후보 몇 건 중 몇 건인지, 고른 8건의 카테고리·매체·빈도,
   그리고 **바꿔 쓸 후보 12건**. 8건 중 4건을 직접 고를 때 이 목록에서 집으면 됩니다.
2. **복붙용** — 아래 형식 그대로. 다른 글자가 한 자도 안 섞여 있어서
   메시지 하나를 복사해 리포트에 바로 붙일 수 있습니다.

```
-서울 아파트값 84주째 올랐다…역대 최장 상승 기록까지 단 1주 (26/9/17,조선일보)
URL : https://www.chosun.com/...
-토허제 실거주 유예, 내년말까지 1년 연장 (26/9/17,조선일보)
URL : https://www.chosun.com/...
```

링크는 단축하지 않습니다. 구글 경유 주소를 언론사 원문으로 펴고 AMP 꼬리만
떼어낸 그대로입니다 (단축은 리포트 쓰는 쪽에서 하는 편이 낫다고 판단).

**고르는 규칙** — 인수인계 문서의 기준을 그대로 옮겼습니다.

| 순위 | 카테고리 | 최대 |
|---|---|---|
| 1 | 주간 가격 동향 (부동산원·KB 주간 아파트값) | **항상 1건** |
| 2 | 정책 (대출 규제·DSR·세제·공급 대책·규제지역) | 3건 |
| 3 | 시장 지표 (거래량·미분양·청약·주담대·분양가) | 2건 |
| 4 | 전월세 (전셋값·월세·임대차) | 3건 |
| 5 | 건설사 수주·재개발·재건축 | 2건 |

카테고리마다 대표 1건을 먼저 확보한 뒤 남은 자리를 점수순으로 채웁니다. 점수순으로만
고르면 매체가 몰려 쓰는 가격동향·정책이 8칸을 다 먹고 전월세·재개발이 통째로 빠집니다.
점수는 `카테고리 배점 + 같은 이슈를 쓴 매체 수 × 1.5` 입니다 — 한 주의 '주요' 뉴스는
매체가 몰려 쓴 뉴스라는 전제입니다.

한 매체에서 최대 2건, 같은 이슈는 대표 1건만 남깁니다. **같은 이슈 판정은 세 겹**입니다.

- 제목 글자 겹침 (bigram, `same_issue: 0.3`)
- 제목 속 숫자 — `84주 연속 상승` 과 `아파트값 84주째` 는 문장이 달라도 같은 사건
- 제목 속 사람 이름 (`per_subject: 1`) — 인사청문회가 열리면 한 사람의 발언을
  매체마다 다른 대목으로 뽑아 써서 제목이 하나도 안 겹칩니다. 이 규칙이 없으면
  8칸의 절반이 한 사람 발언으로 찹니다 (실측: 8건 중 3건)

정치 공방·사설·칼럼·인터뷰·분양 홍보·단신은 `exclude` 로 뺍니다.
`outlets` 에 적힌 34개 매체 밖은 아예 후보에 안 들어옵니다 — 리포트에 적을 매체명이
정해져 있어야 하기 때문입니다.

**언제 나가는가** — 워크플로를 따로 두지 않았습니다. 5분마다 도는 실행에 얹혀 있고,
금요일 08시를 지난 첫 실행에서 한 번만 나갑니다. GitHub 예약은 몇 시간씩 밀리지만
앱스 스크립트 트리거는 제 시각에 깨우므로, 그 실행에 붙는 편이 08시를 잘 지킵니다.
실행이 밀려 토요일에 돌아도 같은 주(지난 금요일~이번 금요일)를 채워 보냅니다.
새벽 01~07시에 걸리면 도장을 찍지 않고 아침 첫 실행으로 넘깁니다.

> 처음 켠 주는 건너뜁니다 (`state.json` 의 `last_weekly` 기준점만 잡습니다).
> 수요일에 설치했는데 지난주 리포트가 느닷없이 오는 것을 막기 위한 것으로,
> 지금 당장 받아보려면 `python src/main.py --weekly-now` 를 한 번 돌리세요.

## 실행은 구글 앱스 스크립트가 깨웁니다

GitHub 자체 예약(cron)은 **믿을 수 없습니다.** 5분 간격으로 걸어둔 워크플로가
49시간 동안 15번 돌았고(간격 중앙값 4시간), 30분 간격으로 걸어둔 워크플로는
하루 세 번 돌았습니다. 그래서 예약은 그물로만 남기고, 실제 트리거는
`apps-script/wake-news-bot.gs` 입니다 — [script.google.com](https://script.google.com)
에 올리고 `setupNewsBotTrigger` 를 한 번 실행하면 **5분마다** 깨웁니다.
구글 서버에서 도니까 제 시각에 뜨고 PC 가 꺼져 있어도 됩니다.

트리거는 **이 하나뿐입니다.** 메시지 응답용 트리거를 따로 두지 않으려고
한 실행이 4분을 듣고 있게 만들었습니다 (아래 참고).

News-Clipper 에 이미 같은 방식이 깔려 있으므로, **그 프로젝트에 파일만 추가하면
토큰(`GITHUB_TOKEN`)을 다시 넣을 필요가 없습니다.** 이름이 겹치지 않게 `NB_`
접두사를 붙여 뒀습니다.

## `news-clipper` 와의 역할 분담

같은 `projects` 폴더의 [`news-clipper`](../news-clipper)와 다루는 종목이 거의 같습니다.
효성중공업 수주 한 건이 양쪽에 다 걸립니다. 그래서 **주제가 아니라 시점으로** 나눴습니다.

|  | news-clipper | news-bot (이 프로젝트) |
|---|---|---|
| **한 줄 정의** | 어제 뭐 있었는지 빠짐없이 훑는다 | 아침까지 기다리면 늦는 것만 알린다 |
| 언제 | 매일 07시 1회 | 뜨는 즉시 (5~15분) |
| 분량 | 32건 (4섹터 × 8건) | 하루 최대 4건 |
| 범위 | 원전·건설·유틸리티·전력기기 | 전력기기·전력망 |
| 무엇을 | **전부** — 동향·해설·전망 포함 | **확정 이벤트만** — 수주, 공시, 낙찰, 정책 확정, 착공, 프로젝트 취소 |
| 형식 | 한 줄 요약 묶음 | 카드 (세부 3~5개) |
| 링크 정리 | 없음 | 있음 (URL 보내면 번역·정리) |

**판단 기준 한 줄**: "오늘 장중에 반응해야 하나?" — 아니면 news-bot은 침묵하고 아침에 넘깁니다.

그래서 이 봇은 아래를 **의도적으로 버립니다**. 전부 아침 다이제스트에서 보게 됩니다.

- 해설·분석·기획·인터뷰·칼럼
- `~할 전망`, `~검토 중`, `~추진`, `~논의` 처럼 확정되지 않은 것
- MOU·업무협약, 전시회·세미나, 시장 규모 전망치
- 단순 주가 등락, 증권사 목표주가 리포트

조정 지점 두 군데:

- **야간 큐를 08시에 풉니다** (`quiet_hours.end`). 07시에 clipper 다이제스트 4건이 먼저
  도착하므로, 같은 시각에 겹치지 않게 한 시간 비켜뒀습니다.
- **원전·유가·일반 클린테크 피드를 뺐습니다.** 원전은 clipper의 원전 다이제스트(8건)가
  전담하고, 나머지는 확정 이벤트가 거의 없어 노이즈만 됐습니다.
  `config.yaml` 의 `feeds` 아래 주석 처리해 뒀으니 되살리려면 주석만 푸세요.

> 봇·토큰·API 키는 양쪽이 공유해도 됩니다 (아래 준비물 참고).

### 1. 저장소 만들기

이 `news-bot` 폴더를 통째로 새 GitHub 저장소에 올립니다.
**이 PC에는 git이 설치돼 있지 않으므로**, 아래 웹 업로드 방식이 가장 빠릅니다.

**방법 A — 브라우저로 업로드 (git 불필요, 권장)**

1. github.com → 우측 상단 **+** → **New repository**
2. 이름을 정하고(예: `news-bot`), **Public** 선택 → **Create repository**
3. 만들어진 페이지에서 **uploading an existing file** 링크 클릭

## 응답 속도에 대한 솔직한 이야기

워크플로는 **하나**입니다 (`bot.yml`). 한 번 깨어나면 이렇게 움직입니다.

```
0:00  수집·선별·알람·클리핑·주간 리포트   (30초)
0:30  ┐
      │  10초마다 텔레그램 확인 — 링크가 오면 그 자리에서 요약    (4분)
4:30  ┘
5:00  앱스 스크립트가 다시 깨움 → 반복
```

앱스 스크립트가 5분마다 확실히 깨우고 한 실행이 4분을 버티므로, **사실상 언제나
누군가 듣고 있습니다.** 링크를 DM 에 넣으면 보통 10초 안팎에 📝 기사 요약 채널에
카드가 올라옵니다. 뉴스 자동 발행은 5분 주기 그대로입니다.

> **왜 별도 워크플로를 두지 않는가.** 예전에는 `worker.yml` 이 30분마다 켜져
> 15초 간격으로 폴링했습니다. 이 저장소에서 유일하게 GitHub 예약에 맡겨져
> 있었고, 실측하니 하루 세 번(00:07 / 04:08 / 07:18)만 살아 있었습니다.
> 나머지 시간에 링크를 넣으면 **아무 답도, 아무 오류도 없었습니다.**
> 별도 워크플로를 두면 그걸 깨울 트리거가 또 필요해집니다. 이미 제 시각에 오는
> 트리거에 얹는 편이 확실하고, 앱스 스크립트도 손댈 필요가 없습니다.

`--messages-only` 로 도는 대기 단계는 수집을 건너뛰므로 회당 몇 초입니다.
겹치는 실행은 `concurrency` 가 줄을 세우므로 같은 링크에 두 번 답하지 않습니다.

> ⚠️ **public 저장소 전용입니다.** 한 실행이 4분 반을 쓰므로 하루 약 1,300분이고,
> private 으로 바꾸면 무료 한도(월 2,000분)를 이틀이면 씁니다. private 이 필요하면
> 대기 단계(`Listen for messages`)를 지우세요 — 응답이 5분 주기로 돌아갑니다.

## 필터 조정하기

`config.yaml` 만 고치면 됩니다. 코드는 건드릴 필요 없습니다.

기본값은 `news-clipper` 와 역할을 나눈 상태(확정 이벤트만, 하루 4건)로 잡혀 있습니다.

**뉴스가 너무 적게 온다** → `limits.min_importance` 를 4 → 3, `limits.min_score` 를 7 → 5 로.
그래도 적으면 `src/summarize.py` 의 "publish=false 로 버려라" 목록에서 몇 줄 지우세요 —
동향 기사까지 받고 싶다면 `해설, 분석, 기획, 전망` 줄을 빼면 됩니다.

**너무 많이 온다 / 관심 없는 게 온다** → `min_importance` 를 5 로 올리면 진짜 큰 건만 옵니다.
계속 거슬리는 유형이 있으면 `blocklist` 에 단어를 추가하세요.

**특정 종목을 챙기고 싶다** → `watchlist.domestic` / `watchlist.overseas` 에 이름을 추가하세요.
워치리스트에 걸리면 점수가 4점 더해져 거의 확실히 통과합니다.

**부동산 주간 리포트를 손보고 싶다** → `weekly` 만 고치면 됩니다.
건수는 `count`, 요일·시각은 `weekday`(ISO, 5=금)·`hour`, 카테고리별 상한은
`categories[].cap`, 검색어는 `queries`, 매체명은 `outlets` 입니다.
비슷한 기사가 두 건씩 들어오면 `same_issue` 를 0.3 → 0.25 로 내리고,
서로 다른 기사가 한 건으로 묶여 버리면 0.35 로 올리세요.
잠시 끄려면 `weekly.enabled: false`.

**야간 알림을 끄고 싶지 않다** → `quiet_hours.enabled` 를 `false` 로.
현재는 한국시간 01~07시에 잡힌 건(중요도 5 제외)을 큐에 쌓아뒀다가 아침 7시 이후 첫 실행 때 한꺼번에 보냅니다.
미국 뉴스가 새벽에 몰려 하루치를 다 먹어버리지 않도록 야간 몫은 `max_night_queue`(기본 3건)로 따로 막아뒀습니다.
아침에 몰아 받는 양을 늘리고 싶으면 이 값을 올리세요.

**점검 도구**

```bash
python scripts/check_feeds.py
```
```bash
python scripts/test_dedup.py
```

`check_feeds.py` 는 피드가 아직 살아있는지, `test_dedup.py` 는 같은 사건을 여러 매체가 썼을 때
한 번만 나가는지를 실제 기사 제목으로 검사합니다. `store.py` 상단의 `DUP_*` 임계값을 건드렸다면 후자를 꼭 돌려보세요.

## 비용

`config.yaml` 의 `model.id` 가 `claude-sonnet-5` 이고 `effort: low` 입니다.
키워드 점수로 1차 선별을 마친 기사만 모델에 보냅니다.
한 번 돌 때 최대 `max_candidates_per_run`(15건)까지만 호출하므로 비용 상한이 여기서 잡힙니다.
실제로는 대부분 이미 처리한 기사라 회당 0~3건 정도만 새로 호출됩니다.

기사 1건당 대략 입력 3천 토큰 + 출력 500 토큰 → **건당 약 15원**, **하루 150~300원** 수준입니다.

요약 품질이 부실하다 싶으면 `config.yaml` 에서 모델을 올리세요. 대신 비용이 약 2.5배가 됩니다.

```yaml
model:
  id: claude-opus-5    # 입력 $5 / 출력 $25 per 1M (sonnet 은 $2 / $10)
```

> 2026-09-15 기준 같은 기사로 두 모델을 비교했을 때, 고르는 기사도 버리는 이유도 수치 정확도도
> 차이가 없었습니다. 기사 요약은 판단보다 정리에 가까운 작업이라 sonnet 으로 충분합니다.

`limits.max_candidates_per_run` 이 모델 호출 수의 상한이라, 비용이 걱정되면 이 값을 낮추면 확실하게 잡힙니다.

`--dry-run` 은 텔레그램으로 보내지 않고 콘솔에만 출력합니다.

(`--dry-run` 없이 쓰면 실제로 텔레그램에 보내고, 이번 주 도장도 찍습니다). (모델 호출은 실제로 일어나 과금됩니다)

> **검증 상태** — 수집·선별·중복제거·본문추출·구글뉴스 링크해석·야간큐·일일한도·렌더링은
> 2026-09-15 실제 뉴스로 전부 돌려서 확인했습니다.
> **Claude 호출 경로만 미검증입니다** (개발 환경에 API 키가 없었음).
> SDK 1.5.0 기준 인자 시그니처는 맞춰뒀으니, 키를 넣고 위 `--dry-run` 을 한 번 돌려
> 요약 카드가 제대로 나오는지 먼저 확인한 뒤 GitHub 에 올리시길 권합니다.

### 중복 제거가 이 봇의 핵심입니다

큰 수주 하나가 뜨면 국내 매체 10곳이 같은 내용을 씁니다. 실제로 테스트할 때
효성중공업 변압기 수주 한 건이 11개 매체에서 후보로 올라왔습니다.

한국어 제목은 조사가 붙어서(`빅테크에` vs `빅테크`) 단어 단위 비교가 통하지 않으므로,
**글자 3-gram 겹침** + **제목 속 금액을 유효숫자 2자리로 뭉갠 지문**을 함께 씁니다.
`3865억원` 과 `3866억` 은 같은 건으로, `1665억원 공급계약` 과 `2200억원 공급계약` 은
제목 틀이 거의 같아도 **다른 공시로** 구분합니다.

### 구글뉴스 링크에 대해

구글은 2024년부터 RSS 링크를 원본 주소가 아닌 내부 ID로 바꿔놨습니다.
`extract.py` 가 비공개 엔드포인트로 원본 주소를 되찾아오며, 2026-09-15 기준 정상 동작을 확인했습니다.
다만 구글이 언제든 바꿀 수 있는 방식이라, 실패하면 조용히 RSS 요약문만으로 카드를 만듭니다.
어느 날부터 구글뉴스發 기사만 내용이 부실해지면 이 부분이 막힌 것입니다 —
그럴 땐 `config.yaml` 의 `feeds` 쪽 직접 피드를 늘리세요.
